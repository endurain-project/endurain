# Security

## Uploads
- All `UploadFile` handling goes through `backend/app/core/file_uploads.py`.
- Route handlers are sync, so persist with `save_validated_upload_sync(file, kind=UploadKind.X, upload_dir=..., filename=...)`
  and read into memory with `read_validated_upload_sync(file, kind=...)`. The `async` variants are for code already on the event loop.
- Never instantiate `safeuploads.FileValidator` elsewhere.
- Never join user-supplied filenames into paths; use server-generated names (UUID/hash/fixed).
- Enforce size limits.

## Access control
- Deny by default; check rights explicitly against the resource.
- Multi-activity bulk reads trust pre-scoped ids and stay behind the owner-scoped contributor; a new caller is a latent IDOR.
- A route that names another user (`{user_id}`) requires an admin scope (`users:read_all`, `users:write`) or takes `CurrentUserId` and checks ownership; `users:read` and `profile` are held by every user.
- Prevent path traversal on any user-influenced path.

## Injection and secrets
- Parameterized queries only; no string-built SQL.
- Shell input via `shlex`; no `shell=True` on user data.
- No hardcoded secrets; read from environment.
- Argon2/bcrypt for passwords; AES-256 for data at rest; JSON, not pickle.

## Outbound requests
- Treat user-provided URLs as untrusted; allow-list host, port, path.
- Egress and SSRF host checks live in `core.network`; add a platform provider, do not call `requests`/`httpx` from `modules.activities`.

## Auth flows
- An OAuth `state` is generated by the server (`secrets.token_urlsafe`), bound to the user, single use and never in a URL.
- Provider tokens are stored encrypted; if a provider rotates a refresh token, a failed write of the new one is logged at `error` because the old one is already invalid.
- New session identifier on login; cookies `HttpOnly`, `Secure`, `SameSite=Strict`.
- Rate limit and lock out auth and password-reset flows.

## Abuse and resource limits
- Bound every request: body size, page size, result size and fan-out; never return an unpaginated list of data that grows with use.
- An expensive read (aggregation, export, stream, render) takes a stricter rate tier than `DEFAULT`.
- A user-triggerable job (import, sync, thumbnail, geocoding) needs a per-user cap or rate tier, a timeout and bounded retries.
- The limiter keys on a validly signed Bearer token, else on `core.network.get_ip_address`; never key on a raw header or read `X-Forwarded-For` directly.
- The application limiter is abuse control; it does not absorb volumetric DDoS, which needs DDoS protection configured upstream of Endurain (`docs/getting-started/advanced-setup.md`).
- Auth and reset responses do not reveal whether an account exists; never log tokens, secrets or API keys.
- Security headers, CSRF and CORS live in `core/middleware.py` and `main.py`; do not widen `allow_origins` or drop a header to make a client work.

When you add a mitigation, state what it protects against; when you flag a vulnerability, explain the risk.
